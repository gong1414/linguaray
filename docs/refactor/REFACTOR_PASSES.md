# Behavior-preserving refactor passes

Each pass below is independently reviewable. The behavior column is the
compatibility boundary; the validation column is the evidence required before
the pass can merge.

| Pass | Current behavior | Structural improvement | Stability proof |
| --- | --- | --- | --- |
| 0. Baseline gates | The resident app switches one host among Settings, Quick Translate, and OCR while preserving `v2` storage, secure secrets, platform permissions, backup, and protocol behavior | Record behavior, public surfaces, platform parity, and the normalized UniFFI callable surface before moving code | Flutter/Rust suites, platform contract tests, golden comparison, macOS build, and the three refactor checklists |
| 1. Dart persistence cleanup | History and glossary are served by application ports backed by Rust | Delete superseded Dart models, stores, utilities, and comments; replace dead-store tests with active repository tests | Repository CRUD/mapping/filter tests, Rust persistence tests, analyzer, and no golden diff |
| 2. Widget reachability cleanup | Product screens use Material 3 and the current `linguaray_ui` components | Delete legacy widget/theme subtrees reachable only from their own tests while retaining the public UI package | Import/reachability search, analyzer, dependency validator, settings/Quick Translate tests, and catalog goldens |
| 3. macOS plugin cleanup | Current text input and result rendering use Flutter widgets; the old platform views and window-appearance channel have no production Dart consumer | Delete the four orphan channels' registration, Swift sources, Xcode references, Dart wrappers, and dedicated obsolete tests | Channel absence test/search, current input and Quick Translate tests, catalog goldens, and `flutter build macos` |
| 4. Settings intent cleanup | General settings renders only its current sections and translation preferences live on the Translation page | Delete the test-only `GeneralSettingsIntentController` and the hidden duplicate dialog chain | General/Translation route tests, target/common-language persistence tests, and settings ViewModel tests |
| 5. Settings navigation convergence | Fourteen stable URLs select fourteen existing settings sections and pages | Make `SettingsDestination` the single location/section definition, retain compatibility re-exports, use an ordinary root redirect, and remove the isolated builder route | Exhaustive location/section uniqueness tests, pending-window navigation tests, debug initial-route tests, and analyzer |
| 6. Provider-rule convergence | Catalog, settings, repository, and streaming translation accept the same provider capabilities and draft constraints | Centralize exhaustive provider capabilities, stable model-ID merging, and pure draft validation while preserving validation at UI and repository boundaries | Table-driven coverage for every `ProviderType`, catalog/model fallback tests, secret tests, settings tests, and streaming tests |
| 7. Flutter composition split | Existing page class names, routes, rendering, and tray/window behavior remain stable | Retain compatibility barrels while splitting root host/tray/routes, Quick Translate coordinator/input/result, settings pages/dialogs, glossary/vocabulary, and pure window positioning | Analyzer, module widget tests, resident-surface tests, and catalog goldens; any unexplained pixel diff fails the pass |
| 8. Settings adapter decomposition | `RuntimeWorkspaceSettingsRepository` implements the same public workspace port and remains the construction entry point | Keep it as a stable facade over focused general, provider, and system collaborators | Existing ViewModel fakes plus adapter mapping/error, secure-secret, JSON round-trip, and dependency tests |
| 9. Rust provider cleanup | Provider traits, configuration schema, defaults, and response parsing remain unchanged | Remove unused private configuration copies, share default-model validation, and replace a suppressed Bing cache field with the actual expiry predicate | Engine tests and `cargo clippy --locked --workspace --all-targets -- -D warnings` |
| 10. Rust capability split | Public Rust paths, serialized settings, Runtime handles, and UniFFI method signatures remain stable | Split platform providers, settings persistence/seed/order/engine mapping, glossary matching/compliance, and Runtime capability implementations; use same-module `include!` fragments for exported Runtime blocks so checksums do not move | Rust format/Clippy/tests, normalized UniFFI snapshot, regenerated-binding diff check, macOS tests, and Windows CI compilation/tests |

No pass changes persisted keys, wire values, secure-storage ownership, route
locations, live platform channel payloads, or exported package symbols.
