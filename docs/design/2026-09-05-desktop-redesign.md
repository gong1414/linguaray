# LinguaRay 桌面视觉重设计

> 此方案对应 99e725f，用户认为改动不足。后续采用[明亮桌面工作区方案](2026-09-05-light-workbench.md)，以该方案为当前设计依据。

## 设计依据与取舍

服务经常阅读外文、截图取词及使用多供应商翻译的桌面用户。快捷窗口的唯一主任务是读懂并处理译文；设置窗口负责配置工具，避免把内部参数作为主视觉。

已阅读 [Linear 的重设计过程](https://linear.app/now/how-we-redesigned-the-linear-ui)、[Raycast 的产品界面介绍](https://www.raycast.com/)、[Apple 桌面排版规范](https://developer.apple.com/design/human-interface-guidelines/typography)。采用 Linear 的导航与内容分层、严格基线对齐；采用 Raycast 的紧凑工具操作密度；字体遵循平台系统字体及中文回退。参考网站用于研究，不引入其图片、图标或品牌资产。

原设计的主要问题：蓝灰背景和青色选中态竞争；正文、表单和导航采用相近的字重；原文输入被边框和尾部按钮挤占；大量边框重复强调每个控件；部分字体仅设 fallback，拉丁字符仍可能使用默认 Roboto。

初版考虑了全黑白，但会弱化 LinguaRay 的辨识度。最终保留品牌蓝用于明确的主操作与阅读标记，其他部分使用中性表面。对比度来自文字与空间，而不是大面积高饱和底色。

## 视觉约定

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 窗口底色 | `#F5F5F6` | `#17181B` |
| 内容表面 | `#FFFFFF` | `#202126` |
| 辅助表面 | `#F0F0F2` | `#1C1D21` |
| 正文 | `#24252A` | `#ECECF0` |
| 次级文字 | `#686B75` | `#AAAEB9` |
| 强调色 | `#2859D9` | `#A5BBFF` |

标题使用系统 Display 字体，22–24 px、中等字重；界面文字使用系统 Text 字体，13–14 px；译文 17 px，行高 1.65；辅助文字 11–12 px。macOS 使用系统 San Francisco 和 PingFang SC，Windows 使用 Segoe UI / Microsoft YaHei UI，不分发平台字体文件。

设置窗采用 204 px 侧栏，右侧完整内容面板；顶层页面统一大标题、清晰组间距和 56 px 左右的设置行。表单边框降低存在感，仅聚焦时突出。导航行高 32 px，圆角按层级使用 6 / 8 / 12 / 14 px。

快捷窗保留动态尺寸和键盘操作。其识别特征为“语言栏 + 两段阅读区域”：原文输入可像文档一样编辑，译文独立排版，小型阅读标记连接两者。工具按钮退至文本之外，避免侵占正文宽度。

```text
快捷翻译                     设置工作区
┌ LinguaRay         工具 ┐   ┌ 导航  ┬────────────────────────┐
│ 自动检测   ⇄    中文   │   │       │ 页面标题               │
├───────────────────────┤   │ 分组  │                        │
│ 原文           辅助操作│   │ 条目  │ 配置组                 │
│ 可直接编辑的完整文本   │   │ 条目  │ 说明 / 控件            │
│                翻译 ↗ │   │       │                        │
├ 译文 · 当前服务 ───────┤   │ 分组  │ 配置组                 │
│ 更适合阅读的译文       │   │ 条目  │                        │
│             复制 / …  │   └───────┴────────────────────────┘
└───────────────────────┘
```

不增加窗口、重复标题栏、启动引导或无关营销文案。保留供应商自动发现、翻译、OCR、历史记录、权限与快捷键等现有行为。通过 Widgetbook、浅深色截图、窄窗口与长内容测试，再进行 macOS 原生检查。


## 实现与视觉复核

- 统一生产 Material 主题，系统字体按运行平台选择；品牌 SVG 和图标源保持原样。
- 设置页采用完整分组导航与内容面板；提供商列表显示模型及密钥保存状态，并支持点击整行编辑。
- 快捷窗采用独立原文与译文区，正文使用完整可用宽度；语言选择、回车提交、朗读、复制、词典和收藏继续沿用原有控制器。
- OCR 采用文档式编辑区，工具栏保留截图、文件、剪贴板、连续识别及复制清空操作。
- Widgetbook 补齐完整导航及已配置提供商场景，更新 macOS / Windows 主题的 60 张浅深色截图。固定测试字体与原生字体分别复核，避免把缺字方块作为视觉基线。
- macOS 原生 Widgetbook 中检查快捷翻译及常规设置的浅深色效果；原生中文与拉丁字体、控件对齐正常。840×560 设置窗、396 px 快捷窗以及长内容和异常状态回归通过。侧栏标题使用有界文本，防止宽字体导致横向溢出。

## 验证

完整 Dart/Flutter 测试 175 项通过（application 25、desktop 108、runtime 2、UI 40）；包含翻译快捷键、模型搜索与选择、异常状态、窄窗口及视觉回归。四个包静态分析、依赖检查、Dart/Rust/Swift 格式检查及 UniFFI 表面基线检查通过。

macOS 原生集成冒烟测试通过，涵盖快捷窗显示、所有设置入口、快捷键注册、系统朗读和内置 ECDICT 查询。随后构建普通 Debug 应用，避免将 Widgetbook 或测试入口当作交付产物。

Windows 的结果是本机生成和校验的确定性主题截图；原生 Windows 集成仍由 Windows CI 验证。
